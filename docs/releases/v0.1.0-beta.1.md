# Puzzary v0.1.0-beta.1

This is the first public beta release candidate for Puzzary, a self-hosted,
extensible puzzle and game library. It is intended for evaluation and
small-scale self-hosting while upgrade compatibility and operational tooling
continue to mature.

## Included

- Web-first administration and player experiences backed by the Puzzary API.
- Ten bundled fallback games: Cross Equations, Crossword, Maze, Minesweeper,
  Nonogram, Spell It, Sudoku, Takuzu, Word Pyramid, and Word Search.
- Installable and independently updateable official puzzle modules.
- PostgreSQL persistence, account permissions, optional OIDC sign-in, Group
  Solve, publishing, uploads, and PDF/PNG printing.
- Docker Compose deployment and first-run administrator setup.

## Install

Download and verify the source archive and its SHA-256 checksum before
extracting it. Then follow [the Docker deployment guide](../docker-deployment.md),
starting by copying `.env.example` to `.env` and replacing every `change-*`
value.

## Upgrade warning

This is beta software. Before upgrading, create and validate a PostgreSQL dump
and back up the application data directory. Do not run an older Puzzary image
against a database already migrated by a newer version. The deployment guide
contains the supported backup, upgrade, restore, and rollback procedures.

## Known release gates

The release tag and checksummed source archive are intentionally withheld until
all issues in the `v0.1.0 Public Beta` milestone are closed. Repository-native
branch protection, secret scanning, and push protection also depend on the
repository becoming public or moving to a GitHub plan that supports them.

After those gates close, the manual **Publish beta release** workflow reruns the
clean-install and upgrade proof, builds a source archive from the exact commit,
attaches its SHA-256 checksum, and publishes the prerelease. The workflow exits
without creating a tag or release while any public-beta milestone item is open.

## Support scope

Report reproducible bugs through the repository issue templates. Report
security concerns privately as described in `SECURITY.md`; never include
credentials, tokens, database dumps, or private deployment details in a public
issue.
